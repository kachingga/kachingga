# V1 — Grupos, gastos y saldos

Lo que se construye ahora. El objetivo es que el grupo de amigos pueda usar la app en el día a día para dividir gastos, sin pagos integrados ni IA.

---

## Features

### Grupos y participantes
- Crear grupos y sumar participantes (sin necesidad de que todos tengan cuenta).
- Editar y archivar grupos.

### Gastos
- Cargar gastos indicando quién pagó y entre quiénes se divide.
- División en partes iguales, por monto o por porcentaje.
- Categoría (comida, transporte, alojamiento, etc.), fecha y descripción.
- Editar y borrar gastos.

### Saldos
- Saldo por persona dentro de cada grupo.
- Sugerencia de transferencias mínimas para quedar a mano.
- Marcar una deuda como saldada **manualmente** (el pago se hace por fuera de la app).

### Filtros
- Por participante (quién pagó / a quién le corresponde).
- Por categoría.
- Por rango de fechas.
- Por rango de montos.
- Búsqueda por texto en la descripción.
- Filtros combinables y guardables.

### Multimoneda
- Cada grupo tiene una **moneda base** (ej. ARS). Monedas soportadas: ARS, USD, EUR, BRL, UYU, CLP.
- Cada gasto (y cada pago manual) tiene su moneda. Si no es la base, hay dos opciones:
  - **Convertir a la base** (default): con un tipo de cambio que se guarda en el gasto. Por defecto es el **dólar blue promedio** (`(compra + venta) / 2`, ej. compra 1545 / venta 1565 → 1555), sacado de [DolarApi](https://dolarapi.com/v1/dolares/blue) — misma cotización que muestra dolarhoy.com. Se puede pisar con uno manual. El automático solo existe para ARS ↔ USD; para otras monedas el tipo de cambio es obligatorio.
  - **Mantener la moneda** (`keepCurrency`): "este gasto es en USD, pagame en USD". No se convierte y genera un saldo aparte en esa moneda.
- Los saldos se muestran por moneda: primero la base, después una por cada moneda "mantenida".

## Modelo de datos

Schema completo en `apps/api/src/db/models/*.prisma`. Resumen:

| Modelo | Qué es |
|--------|--------|
| `Group` | Nombre, `baseCurrency`, `inviteCode` único, `archivedAt` |
| `Participant` | Persona dentro de un grupo. `userId` (Supabase) es `null` hasta que alguien se une con el código y la "reclama". Único por `(groupId, userId)` |
| `Expense` | Descripción, categoría, fecha, `amountCents`, `currency`, `exchangeRate`, `splitType`, quién pagó. Borrado lógico (`deletedAt`) |
| `ExpenseSplit` | Parte de cada participante en un gasto, ya resuelta en centavos (siempre suma el total). En `PERCENTAGE` guarda también el porcentaje |
| `Settlement` | Pago manual entre dos participantes ("ya te pagué"), con las mismas reglas de moneda. Borrado lógico |
| `SavedFilter` | Filtros de gastos guardados por usuario y grupo (JSON validado con el schema `expenseFilters`) |

**Reglas clave**
- **Montos en centavos enteros** (`amountCents: Int`) en la moneda del gasto. Límite: ~21,4 millones por gasto (int4 de Postgres).
- **Moneda de un gasto/pago** → en qué saldo cuenta:
  - `currency == baseCurrency` → saldo base, `exchangeRate = null`
  - otra moneda con `exchangeRate` → saldo base, convertido (1 unidad = `exchangeRate` de la base)
  - otra moneda con `exchangeRate = null` → saldo propio en esa moneda
- **División**: `EQUAL`, `AMOUNT` (los montos tienen que sumar el total) o `PERCENTAGE` (tienen que sumar 100). Los centavos que sobran al redondear van a los restos más grandes, así cada gasto suma exacto.
- **Saldos**: positivo = le deben; negativo = debe. Al convertir se convierte cada parte y al pagador se le acredita la suma, así cada moneda siempre suma cero.
- **Transferencias mínimas**: greedy (el que más debe le paga al que más le deben), como máximo `n - 1` transferencias.
- **Acceso**: solo ven un grupo los usuarios que tienen un participante vinculado. Si no sos miembro, la API responde `NOT_FOUND` (no revela que existe).
- **Grupos archivados**: se pueden ver pero no modificar (salvo desarchivar).
- **Quitar participantes**: solo los que no tienen cuenta y nunca aparecen en un gasto o pago.

## Procedures tRPC

Todos requieren login (`protectedProcedure`) salvo `health.ping`. Inputs en `apps/api/src/schemas.ts` (la app los importa desde `@kachingga/api/schemas`).

| Procedure | Tipo | Qué hace |
|-----------|------|----------|
| `health.ping` | query | Público. Chequeo de vida |
| `health.me` | query | Usuario logueado (id, email) |
| `groups.list` | query | Mis grupos (`includeArchived` opcional), con cantidad de participantes |
| `groups.get` | query | Grupo + participantes (`isMe`, `hasAccount`) + `myParticipantId` |
| `groups.create` | mutation | Crea el grupo y mi participante (`myName`) |
| `groups.rename` | mutation | Cambia el nombre |
| `groups.setArchived` | mutation | Archiva / desarchiva |
| `groups.regenerateInviteCode` | mutation | Nuevo código (el anterior deja de servir) |
| `groups.preview` | query | Por código: nombre, moneda, participantes sin cuenta y si ya soy miembro |
| `groups.join` | mutation | Unirse por código: reclamando un participante (`participantId`) o como nuevo (`name`) |
| `participants.add` | mutation | Agrega alguien sin cuenta |
| `participants.rename` | mutation | Renombra |
| `participants.remove` | mutation | Quita (solo sin cuenta y sin movimientos) |
| `expenses.list` | query | Gastos con filtros combinables, paginado por cursor (50) |
| `expenses.get` | query | Un gasto con sus partes |
| `expenses.create` | mutation | Crea (resuelve partes y tipo de cambio) |
| `expenses.update` | mutation | Reemplaza todo el gasto y sus partes |
| `expenses.delete` | mutation | Borrado lógico |
| `settlements.list` | query | Pagos manuales del grupo |
| `settlements.create` | mutation | Registra un pago manual |
| `settlements.delete` | mutation | Borrado lógico |
| `balances.get` | query | Por moneda: saldo de cada participante + transferencias sugeridas |
| `savedFilters.list` / `create` / `delete` | query / mutation | Filtros guardados (solo los míos) |
| `rates.blue` | query | Blue actual: `buy`, `sell`, `mid`, `updatedAt` (para precargar el tipo de cambio) |

**Filtros de `expenses.list`** (`expenseFilters`): `paidById`, `splitParticipantId`, `categories[]`, `dateFrom`, `dateTo`, `minAmountCents`, `maxAmountCents` (en la moneda de cada gasto), `search` (descripción, sin distinguir mayúsculas).
